# RPT8-17: provenance without executable overhead

Decision: **go for zero-overhead sideband source locations on the bounded fixture;
no-go for exact entry ownership from source maps alone.** Enabling existing
AssemblyScript source maps and removing only the diagnostic `sourceMappingURL`
section restores byte-identical baseline Wasm in all four tested configurations.
A separate counterexample demonstrates the remaining loss: two distinct source
functions merge into one final body, whose map retains only one representative
source location. That location cannot establish exclusive ownership.

No production compiler, partitioning, optimizer, Report metric or schema changes
are introduced. This is an explicitly invoked evidence task, outside aggregate
profiles. The Catalog gate remains closed because exact-owner attribution failed
on a small counterexample. No Catalog compile was attempted.

## Reproduce

From the repository root with lockfile-pinned workspace dependencies:

```bash
node docs/internal/rpt8-17/probe.cjs
```

The probe reuses the existing entry-proof harness. A separate test copy adds
`--sourceMap` and a passive map observer to its asc invocation; no compiler file
is patched on disk. The observer returns the original emission unchanged. The
proof strips the URL custom section in memory solely for comparison, preserving
all other sections. It asserts that removal does not shift code offsets.

Temporary Wasm, generated source and maps are deleted. Stdout records bounded
location counts, sizes, compilation timings and the gate decision. Raw maps and
source content are not checked in or added to the report capsule.

## Where provenance survives and disappears

| Stage | Existing evidence | Limitation |
| --- | --- | --- |
| Canonical plan and control lowering | Stable routing entry IDs; control blocks retain `entryId` or shared implementation identity | Generated control and shared stages are separate ownership cases |
| Dispatcher layout | Exact program-counter cases and original control blocks | Several entries can share one chunk |
| AssemblyScript emission | Cases can be joined back to source positions without rewriting generated code | No entry-owner metadata is embedded in ordinary expressions |
| Optimized source map | Final Wasm offsets map to source points | A source point does not encode the union of origins after merging |
| Final artifact | Exact physical bytes and body boundaries | Adjacent map anchors do not establish exclusive byte intervals |

The location diagnostic joins generated `__pulse_pc` case clauses to the actual
control blocks from that invocation. Shared stage identities resolve to their
recorded registrations. It counts **single-entry source hints**, **shared-entry
source hints**, **generated-control source hints** and **unknown origins**.
Separately emitted expression/runtime source points outside these case regions
remain unknown in this projection.

These categories describe the source location, not final instruction ownership.
All exact exclusive/shared/generated byte totals remain `null`. The decoder never
charges bytes between neighboring source-map anchors to the preceding owner,
never distributes shared bytes among entries, and never converts missing anchors
into zero-sized handler code.

## Byte-identity and semantic evidence

The Pulse fixture includes conditional early response/`next`, explicit error
transfer/recovery, repeated effectful middleware and shared stages. Both continuing
registrations have final mapped case locations in each tested configuration.

| Target / optimization | Baseline Wasm | With map URL | After URL removal | Raw sideband map |
| --- | ---: | ---: | ---: | ---: |
| Portable / default | 7,406 B | 7,436 B | 7,406 B, identical | 10,388 B |
| Fastly / default | 42,903 B | 42,933 B | 42,903 B, identical | 57,815 B |
| Portable / bounded-size | 7,043 B | 7,073 B | 7,043 B, identical | 9,582 B |
| Fastly / bounded-size | 36,591 B | 36,621 B | 36,591 B, identical | 46,459 B |

`bounded-size` is `experimental-native-bounded-size`. No extra entry partitions,
retention annotations or dispatch calls are introduced. Generated source and plan
bytes are unchanged. Seven request cases run on baseline and mapped artifacts in
every cell: 56 executions with response/body/effect-count assertions. The stripped
artifact is byte-identical to the already-executed baseline. Fastly uses the local
test host, not deployment or Viceroy.

Generator+asc+capture wall times are printed per cell. They include metadata and
observer cost, with baseline first, and are single samples rather than a speed
claim. Final pairs were 1,974 → 2,264 ms, 4,318 → 4,303 ms, 2,310 → 2,222 ms and
3,550 → 3,385 ms in table order. Repeat timings vary. This measures neither runtime
throughput nor RSS. Sideband growth is reported separately from executable size.

Location coverage is recorded independently from bytes:

| Target / optimization | Single-entry hints | Shared-entry hints | Generated-control hints | Unknown origin |
| --- | ---: | ---: | ---: | ---: |
| Portable / default | 507 | 119 | 74 | 1,233 |
| Fastly / default | 597 | 490 | 49 | 9,987 |
| Portable / bounded-size | 513 | 128 | 75 | 1,086 |
| Fastly / bounded-size | 468 | 591 | 54 | 7,967 |

These are location anchors, not byte coverage. Exact byte ownership remains
unproven in every category, including anchors with a single-entry source hint.

## Merging and elimination counterexample

`shared-origin.cjs` compiles two distinct exports with identical `value + 7`
bodies, plus a function containing a constant-false branch. It uses the production
bounded-size optimization argument builder. The final export indices prove that
the two source functions share one physical body; its map contains only one of
the two source lines. Treating that line as an exclusive owner would be false.
The eliminated branch has no map anchors; that fact alone would not generally
prove an authored handler has zero bytes.

Both baseline and mapped/stripped counterexample binaries match exactly. Runtime
checks exercise both aliases and the surviving branch. The result is a positive
byte-identity proof and a negative ownership proof, not an optimizer defect.

## Next decision

A source-location navigation feature could use this mechanism with explicit hint
labels. Exact attribution needs evidence that carries **sets of origins** across
optimizer transformations and associates those sets with final emission. Before
committing to that work, inspect whether a bounded hook can observe merging,
inlining and elimination without altering executable optimization; do not assume
a source map or a stripped instrumentation pass supplies this information.

Any production design must bind sidecars to the final stripped artifact hash and
preserve offsets, custom-section policy, historical replay and byte-identity
checks. This proof does not publish its mapped artifact's existing sidecar as
valid for the stripped artifact. An optimizer fork or changed optimization recipe
requires a separate cost/architecture decision. RPT8-14 remains the production
containing-body view; RPT8-15's extra partitions are not promoted.
