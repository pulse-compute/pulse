The existing Example 12 project retains its five-tool v1 Node host and behavior.
A contained `application/` project introduces the v2 compiled MCP entry with only
`pulse.start`. This uses the existing one-entry-per-project config contract;
there is no new profile-specific entry override. Its explicit profiles are Node
Native (default), Fastly Native and Node JavaScript. The existing MCP host package
API is preserved, and migrated discovery does not advertise unfinished tools.

from `codex/b10-mcp-05-wip` at `0b33b3c`. No PR #438 machinery is imported. The new
managed operation is one direct `ctx.call` into an imported synchronous function;
ordinary computation admission, schema conversion, resources, instrumentation and
generation remain the owners. The first probe replaced an unsupported pure-string
helper form with existing bounded computation loops; compiler rules were not widened.

`pulse.start` returns the full canonical schema for all four goals and both Node
starter target choices: dependencies and exact package versions, configuration,

Runtime provider selection is independent of the requested starter target.
Structured invalid-version/selection/goal outcomes preserve the existing behavior;
metadata explicitly identifies application v2. Protocol budgets and server package
version are generated from existing canonical config/corpus owners.

## Deterministic generated closure

`scripts/pulse-context-start.json` owns finite goal/tool metadata. The existing
context builder invokes `pulse-context-start.cjs` to materialize the computation
and MCP entry from `application/src/*.template.ts`, copy the canonical schemas,
and emit config from `application/.pulse/config.template.ts`. Resource manifests,
all source/config inputs and generated outputs are bound into the existing build
manifest. Check mode reconstructs and compares 22 files including installed CLI
mirrors, rejects stale/missing/corrupt inputs and never repairs them. Generation
uses the release-pinned Node 24.18.0.

Cited configuration text is read from `context.text`, including the explicit
Native-to-JavaScript target substitution. Generated code contains only plan
metadata; it never imports the full-text corpus module. All selected cited text
remains in the resource owner. Artifact tests inspect materialized initial Wasm
memory because the optimizer may split zero-filled data ranges; each Native
artifact has exactly one full-text resource backing. Full installed resource
closure remains a later checkpoint.
