# B10-MCP-05D: explicit Node JavaScript computation calls

05D (#445) continues draft #442 after 05C. A named plain handler on explicitly
selected Node JavaScript can invoke the same imported synchronous project
functions through `ctx.call(target, input, {inputSchema, outputSchema})`.
This remains an internal implementation checkpoint; supported types, diagnostics
and public contract finalization belong to 05G.

The JavaScript planner uses the existing reachable project graph, project
function resolver, callable source admission, ordinary pure-helper composition
and independent Native computation validator. It does not require Native
eligibility for the rest of the JavaScript caller. Callees retain the existing
bounded computation language. At most 16 static sites/targets are admitted;
loops around calls, nested/awaited calls, dynamic targets, context escape and
indirect call-method references are rejected. Registered schema pairs stay
literal and consistent for each defining target identity.

The plan carries a fixed table of defining identities, imported bindings, schema
pairs, selected resources and per-target static-site counts. Its identity includes
these facts. Source realization adds a collision-free private export of the
selected imported function references in the caller's defining module. The CLI
loader and Node source packager share that realization; source hashes are checked
before augmentation. Named aliases, target re-exports and a re-exported default
handler preserve identity. The provider binds the table once to the loaded
application. There is no application registration API or runtime target discovery.
The optional provider binding hook and runtime host implementation export are
private integration plumbing, not a new supported authoring surface.

Only bound HTTP applications receive `ctx.call`. Each invocation validates and
copies input using the existing schema round-trip, then adds readonly access with
call-lifetime checks. The callee receives only `resources` and `workspace`.
Their existing implementations enforce resource reads, finite numeric cells and
allocation limits, under a fresh child lifetime that checks the parent request
budget. Only the callee's admitted resource IDs can be mapped. HTTP, state,
effects, nested calls and codec methods are not exposed in the computation
context; boundary conversion remains owned by the existing codecs.

Output passes complete schema validation and normalization before return. It is
detached from input and execution-owned views. A `finally` closes the child frame
on success or failure. Retained inputs, views, workspaces and their allocation
methods fail after return; a retained `ctx.call` fails after the request closes.
Counts belong to the request, never to the application. Calls neither reset nor
extend its deadline. Unexpected Promise/thenable results fail synchronously;
invalid host Promise rejections are observed to avoid unhandled rejections.

## Evidence and failure envelopes

`callable-authored-javascript` executes real authored calls on Node Native, the
JavaScript graph loader, CLI preparation, and the built Node source package.
Its shared corpus covers nested records, present/absent optional fields, Unicode,
helper composition, aliased sites and independent zeroed workspaces. Additional
checks exercise re-exported entry loading/packaging, changed-source rejection,
invalid output, source admission failures and adversarial trusted-host fixtures
through the actual `ctx.call` boundary. Trusted-host fixtures are deliberately
outside source admission so they can test otherwise unreachable defensive checks.

Source failures retain the shared callable admission diagnostics. Invalid output
uses the existing schema encoder: Node JavaScript contains an unhandled handler
failure as HTTP 500; the Native host API reports `PULSE_SCHEMA_ENCODE`. Illegal
runtime ownership/pair/target/count/async operations raise
`PULSE_CALL_BOUNDARY_INVALID`, subject to ordinary handler containment. Closed
parent executions and expired deadlines retain their existing runtime codes.
These envelopes do not claim identical HTTP error bodies across targets.

This is original-source JavaScript execution, not a sandbox. Source admission
bounds the computation language; parent checks enforce request lifetime at the
boundary and resource/workspace operations. No JavaScript loop instrumentation,
new deadline implementation or Native-to-JavaScript fallback is introduced.

The unchanged Native authored baseline gate remains in force. Full functional
profiles, cumulative-budget and exceptional-cleanup qualification, installed
closure, provider/client reality and sealing remain later checkpoints. No Fastly
JavaScript MCP support is claimed. Next: 05E (#446), Router and managed MCP callers.
