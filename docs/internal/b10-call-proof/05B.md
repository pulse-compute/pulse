# B10-MCP-05B: one authored Native call

The named plain Native project entry now connects `admitCallableSource` to the
ordinary caller compiler and Native plan builder. This is the bounded 05B
checkpoint for #443 on the #442 lineage. Public types/support are still 05G;
router and managed MCP authoring are 05E, JavaScript is 05D.

```ts
import { query } from './query';
export default async function handler(ctx) {
  const result = ctx.call(query, { value: 2 }, {
    inputSchema: 'proof.Input',
    outputSchema: 'proof.Output',
  });
  return ctx.json(result, { schema: 'proof.Output' });
}
```

The project must register these schemas through its ordinary `schemas` input.
The target is one imported named synchronous project function `(ctx, input)`.
Named aliases and re-exports retain the ordinary resolver's defining identity.
The admission pass stays non-executing; only full caller lowering can produce
an executable plan. The Native builder checks each admitted site, lowers its
argument through the ordinary expression/ownership rules, rejects known scalar
inputs and attaches the validated callee plus its selected resources before
hashing and independent plan validation. The existing shared backend validates
and copies input/output with the registered codecs at execution.

Only resolver-consumed import bindings are admitted. The ordinary linker still
rejects other runtime value references; no package lowerer or resolver trust is
added. An entirely unused named project-function import resolves through that
same linker without compiling the function body. Its resources and callable
support remain absent. Original caller locations are retained at call sites.

The implementation reuses the existing callee frontend, canonical generator,
resource/workspace code and request bounds. It adds no Entities primitive
emitter. Calls remain synchronous, outside loops/nested functions/call arguments,
with one resolved target and up to 16 sites. Helpers and multiple targets await
05C; failure/cleanup qualification remains 05F.

The authored fixture includes a binary resource, numeric workspace, bounded
loop and exact Unicode result, plus an alias/re-export, full caller/target/schema
rejections and unused-function elimination. It executes the actual authored
HTTP handler on Node Native and injected Fastly Native. It does not establish
Viceroy/deployed behavior or MCP authoring.

The zero-use baseline comparison has two deliberately explicit levels:

- No-call source is compiled independently through both complete toolchains.
- The untouched frontend rejects unused runtime imports. For imported-unused,
  its backend compiles the exact new call-free plan; emitted Wasm hashes and
  imports must match on both targets. Comparing no-import versus unused-import
  in the new compiler also requires equal byte counts/imports and identical
  AssemblyScript apart from the embedded source-bound plan hash. The hashes
  between those two different source inputs are intentionally different.

Do not remove source identity to manufacture cross-source hash equality. The
retained receipt records which comparison was made and the exact baseline.
Validation results and recovery state are in `05B-VALIDATION.md`.
