# 05E — reachable Router and managed MCP callers

05E (#446) continues draft #442 after 05D. An ordinary routed HTTP handler and a
managed MCP operation now invoke the same imported computation through authored
`ctx.call`. Node Native, injected Fastly Native, and explicitly selected Node
JavaScript use the existing shared computation implementation.

## Ownership and admission

The shared source admission accepts the caller descriptors selected by the Router
frontend and managed-handler compiler. A project collection resolves imported
identities, enforces consistent registered schema pairs and the sixteen-site
bound, and deduplicates callee plans. Reused Router handlers count each reachable
occurrence toward the static limit and JavaScript execution budget.

Router normalization carries compiler-owned site identifiers through synthetic
source. Native lowering checks the selected schemas and target identity and
requires every selected source site to be lowered. Managed expression lowering
emits the existing callable-call form with its validated table index. The trusted
terminal application assembler includes shared callable code generation; Entities
keeps its existing invocation adapter and MCP keeps protocol/dispatch ownership.
No resource, workspace, loop, or schema emitter was added to Entities or MCP.

The JavaScript planner uses the same canonical reachable-caller admission. Its
original source modules expose a private static target array; the loader and Node
source packager collect only the selected entries and bind them to the application
function or Router object. Multiple caller modules retain their own imported
bindings. Request ownership, schemas, resources, workspace lifetime and deadlines
continue through the 05D boundary.

Calls remain synchronous, imported, schema-bound and outside loops/nested
functions. Dynamic/indirect targets, context escape, unsupported callee behavior,
unknown schemas and conflicting pairs fail admission. Unselected managed handlers
do not contribute call sites or schema references. Callable bodies own their
helper graphs; the Router helper scan inspects handler-owned calls only.

## Evidence and remaining work

`callable-authored-routed` executes real source through both Native providers,
the JavaScript graph loader and built Node packages. It checks multi-module
bindings, reused and inline routes, source rejection, dormant managed operations,
and no-call/imported-unused emission. Its optional baseline mode compares complete
Wasm hashes, sizes and imports against untouched `8a51d70`: identical no-call source
uses the baseline compiler; imported-unused call-free plans use its backend because
the earlier frontend does not admit those imports. No hash is stripped from the
byte comparison.

The exact terminal checks and revision identity are recorded in
[05E-VALIDATION](./05E-VALIDATION.md). This is the focused integration checkpoint;
full profiles remain deferred by the user's explicit direction. Injected Fastly
is not deployed-provider qualification. Failure/cleanup and cumulative budgets
remain 05F (#447); public authoring/types remain 05G. No five-tool application
migration, installed closure, release seal, merge, or deployment is included.
