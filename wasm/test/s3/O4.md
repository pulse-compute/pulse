# O4 — S3 package and consumer acceptance

O4 adds `@pulse-compute/s3` to the synchronized `1.0.0-beta.1` candidate as a
supported extension. The release now contains 19 packages. The public API is
the package root; provider and lowering exports remain trusted toolchain
integration. Version, registry bootstrap, publication and activation gates
are unchanged. No npm publication or live origin acceptance is claimed.

## Acceptance contract

| Evidence | Executions per package set |
| --- | --- |
| 68 read cases on Node Native, Node JavaScript and Fastly Native | 204 |
| 38 write cases, including target-specific cancellation and partial-write cases | 108 |
| Public declarations from an isolated install | Strict TypeScript check, without workspace paths or skipped library checks |
| Package closure | 19 exact-version tarballs; all installed Pulse file bytes checked before and after execution |

The same corpus runs from source and installed tarballs. Read coverage includes
exact key encoding, raw-byte digest, UTF-8/BOM handling, byte and metadata bounds,
duplicates, missing/wrong lengths, truncated streams, transport loss, origin
statuses, credential failure, deadlines and nonempty redaction evidence. Writes
cover exact sent bytes, independent SigV4 verification, PUT/HEAD/GET flow,
parallel effects, complete rejection versus uncertain acknowledgement, failed
body completion, deadlines and cancellation without rollback.

Both consumers use generic JSON responses (`strict: false`) to compare complete
S3 result unions. This does not relax S3 byte validation. Application strict
JSON responses still require response schemas.

The clean-machine gate starts the existing loopback read-only candidate
registry, installs exact tarballs, then launches an isolated consumer process.
Every product module is loaded from installed package exports. Native Fastly
builds use the installed CLI/provider and packaged lowering. The repository
host ABI fixture supplies only the external platform for the resulting Wasm;
it imports Node builtins and receives no workspace realization. Source product
modules in the consumer's CommonJS cache fail acceptance.

The artifact supervisor compares installed bytes to each tarball, recognizing
npm's `.gitignore` to `.npmignore` extraction rename. It
does not modify installed packages. Its separate process keeps workspace
packing/documentation helpers out of the consumer module graph. The report
`s3-packed-acceptance.json` records every tarball's SHA-256 and each target's
execution counts in the clean-machine task directory.

## Reproduce

Run from the repository root after restoring the pinned dependencies:

```sh
corepack pnpm@10.0.0 build
node wasm/test/s3/run-native-read-acceptance.cjs
node wasm/test/s3/run-write-acceptance.cjs
node wasm/test/release/assert-release-packages.cjs
node wasm/test/release/assert-clean-machine-acceptance.cjs
node wasm/test/release/assert-artifact-determinism.cjs
```

`release-packages` checks S3's facade, types, contract, protocol, compiler and
AssemblyScript payload plus both providers' S3 dependencies and Crypto's
JavaScript byte realization. `clean-machine-acceptance` includes the packed
S3 replay in the existing release gate. Determinism compares independently
packed release sets and documentation sites.

## Following work

Fastly JavaScript remains ineligible for the raw-header limitation documented
in [O3](./O3.md). It is not a gate for these three supported targets.

Live Object Storage evidence follows T2 and must record the actual endpoint,
region, credential mapping, target artifact identity, exact object bytes and
observed acknowledgements. Local host fixtures and the Node TLS fixture do not
establish live origin compatibility or durability. Conditional KV, Terraform
activation, Catalog migration, and Assets alignment remain separate work.

M1 can consume the exact compatible package set produced by `release:pack`,
using the emitted manifest's tarball paths and integrity hashes. Do not use
floating npm tags, workspace aliases, source deep imports or edits to installed
dependencies to bridge a missing package or lowering contract.
