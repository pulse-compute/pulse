# O2 Native read evidence

O2 implements the read part of O1 through the real `@pulse-compute/s3` facade,
package-owned builder, canonical package effects and both Native providers.
The Native profile runs `s3-native-read` and `s3-node-transport`; the Unit profile
runs `s3-read-contract`. The corpus lives in `packages/s3/conformance/read.json`.

The shared read acceptance compiles actual consumer modules for Node Native and
Fastly Native. It verifies independent SigV4 signatures, token signing, fixed
clock formatting, literal binding preservation, dynamic keys, parallel reads,
raw UTF-8/BOM/NUL text, SHA-256, exact and excessive body sizes, maximum JSON
escaping, duplicate/oversized metadata, HTTP outcomes, missing credentials,
request/body deadlines, and private Native effect traces. The Fastly host fixture
also checks cache PASS and disabled automatic decompression. This is local ABI
evidence; no live bucket or deployed Fastly service was used.

The Node transport test starts an ephemeral HTTPS origin trusted only through
its generated local test certificate. It proves raw header UTF-8 conversion,
duplicate preservation, exact body bytes, manual redirect handling and abort.
It requires OpenSSL to generate that certificate. Crypto's Native source test
covers digest/MAC known answers, short and maximum keys, pointer/length errors,
reused and wiped staging memory, and unchanged JWT verification minimum keys.

## Resolved contract details

- The package runtime uses one `providerKind`, so it is `s3`; operation kinds
  remain `s3.head` and `s3.getText`.
- Crypto permits 8192-byte internal MAC keys. The provider secret limit remains
  4096 bytes; the SigV4 `AWS4` prefix requires more than a 4096-byte primitive.
  JWT verification keeps its separate 32–4096-byte key contract.
- HTTP header values are interpreted as strict UTF-8 on both providers. Node's
  Latin-1 representation of wire bytes is converted before metadata validation.
  Access IDs and session tokens use visible ASCII without whitespace.
- Deadline accounting uses a monotonic clock and includes credentials, signing,
  response headers and body consumption. Reads have no automatic retry.
- Fastly waits through `fastly_async_io.select` and nonblocking
  `pending_req_poll_v2`; readiness need not mean a final response. A zero
  remaining timeout never becomes the ABI's unlimited wait. Acquired response
  and body handles are closed. `send_async` consumes request/body handles.
  Pending requests have no cancellation hostcall: timeout discards the pending
  read and stops waiting, without promising origin cancellation. Invocation
  termination remains provider-owned. See the
  [pending-request contract](https://docs.rs/fastly/latest/fastly/http/request/struct.PendingRequest.html),
  [timeout adapter](https://docs.rs/fastly/latest/src/fastly/async_io.rs.html), and
  [host ABI source](https://docs.rs/fastly-sys/0.11.12/src/fastly_sys/lib.rs.html).
- Fastly's general JSON string escaper now uses linear allocation. Its previous
  repeated concatenation trapped for a valid 32 KiB all-NUL object. The maximum
  JSON-escaping acceptance case keeps the package's full text bound enforceable.

The package remains private. O3 owns PUT and JavaScript realization; O4 owns
packed-consumer/release promotion. Assets are unchanged. Live origin evidence
belongs to the later infrastructure phase.
