### The old JavaScript loader blocker is stale for this tested target

The unchanged installed JavaScript application loads Entities and invokes both
operations. The test failure is not an unexported `dist/index.js` error.
`lookupCustomer` asks for `.text()`, while its fixture declares
`{ value: 'Ada Lovelace' }`. The Node JavaScript fetch adapter intentionally
JSON-serializes `value`, so the returned display name is `"Ada Lovelace"`
(including quotes). The expectation asks for the unquoted string.

A controlled **consumer-only** experiment changed just that fixture to
`{ text: 'Ada Lovelace' }`: both JavaScript cases passed, exit 0. The original
fixture was restored immediately. Source handlers, expected values and installed
package bytes were unchanged. This localizes the example failure without
claiming all Entities JavaScript shapes are qualified.

Next EN-01 should repair/qualify this ordinary example and retire the stale
Node JavaScript loader prose. Do not widen private package exports or implement
a speculative loader rewrite. Keep the broader EN-04 contract corpus and
EN-05 clean-consumer coverage separate.
