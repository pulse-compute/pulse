# B6-08-F02: packed read-loop deadline clock isolation

The complete seal on merged `10d122e91c96488f766f96fb281053baca0c6725`
returned a terminal failure after 34m 5s: 161 tasks passed, the packed
clean-machine task failed, and three tasks were unreached. Its cumulative
read-loop deadline assertion reported `Missing expected rejection`. An unchanged
focused clean-machine rerun passed, including all 53 read-loop checks. That
rerun does not replace the failed seal.

The fixture used a fake request clock with a 10ms budget, advancing 4ms per
fetch. The S3 reader also caps its real timeout by the remaining request budget.
This left a real timeout as short as 2ms competing with signing and body reads.
A typed S3 timeout could end the route before virtual request expiry.

A regression inserts a 25ms delay in the deadline case's fixture fetch. With the
original 10ms/4ms clock, exact installed acceptance reproduces the missing
rejection on Native Node. The fix uses a 10000ms virtual budget and 4000ms
advances, preserving the three-fetch deadline while keeping the existing 1000ms
S3 binding timeout clear of the intentional delay. The virtual duration adds no
wall-clock wait. The 25ms delay remains as regression coverage.

The exact `PULSE_REQUEST_DEADLINE_EXCEEDED` rejection, three fetches, and zero
pending virtual timers remain mandatory on Native Node and JavaScript. Assertion
messages now identify the target. The full corpus still has 53 checks and
verifies package closure, unchanged installed bytes and no workspace product
modules. Production clocks, timeouts, error handling, package contents and CAS
semantics are unchanged.
