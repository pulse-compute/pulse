# GEN01 — residual generated-code and compiler-cost census

This evidence pass measures the current Fastly Native generator at `b87b88b607e9520dcc22edb98818afcffe50094d` (merged MEM02). It changes no production emitter, optimizer, ABI, or target behavior. The opt-in task `compiler-generated-census-gen01` produced [the complete 21-sample ledger](gen01-census-evidence.json), status `passed`. Three serial, isolated processes compiled each cell with the default optimization profile; every cell produced one stable final-Wasm SHA-256 across samples. `WebAssembly.validate` passed for every sample. The report records the lockfile, source-owner and harness hashes, Node and AssemblyScript versions, fixture hashes, and the dirty working-tree state at measurement time.

The source partition runs against **final instrumented Fastly source**. It matches names against the actual portable generator and byte-exact schema/provider stages, classifies top-level declaration ranges once, then assigns unmatched declarations and non-declaration text to runtime support. The five categories reconcile to the complete source byte count in every cell. Classification is **source ownership**, not exclusive retained Wasm or additive compiler time. Package/effect adapters include the effect-result and dispatch stages plus package-owned S3, time, digest, KV and invocation source. Dispatcher/handlers include portable generated expressions, chunks, stepping and effect-result handoff. Runtime support includes the Fastly base, request helpers, driver and any unmatched instrumentation. This classification intentionally keeps shared parsing in runtime support, even when other categories call it.

The fixture uses one referenced `R0 { id: string; tag: string }`; other registered IDs are unused by handlers but still emitted. For repeated schemas the root shape is identical across IDs. For diverse schemas, `R0` stays fixed while other IDs vary in field name, scalar/array type and nested key. Route controls repeat an equivalent async handler. Effect controls independently raise the number of `config.get` sites per route. Thus `8 routes × 3 sites` contains 24 sites, while `1 route × 3 sites` contains three. This is a synthetic shape and a single effect kind, not a whole-app sample or an effect-kind diversity experiment.

Median planning time ranges from 133–220 ms, median total worker build time from 2,679–6,040 ms, and median worker peak RSS from 118–146 MiB. Neither RSS series is additive. The largest five optimized **code-section body ordinals and sizes** and total body bytes appear per sample in the ledger. No source function name is assigned to an optimized body without a matching name-section companion: for example, the 16-diverse cell's largest body is ordinal 143 at 4,010 bytes, while the baseline's is ordinal 136 at 2,263 bytes.

The largest source declaration in the 32-repeated cell is provider `__pulse_fastly_schema_apply` at 11,164 bytes (5,660 for 16 repeated IDs), followed by the shared `__PulseJsonParser` at 6,512 bytes. In the 8-route/3-site cell, portable `pulse_set_effect_result` is 6,028 bytes and provider `__pulse_fastly_resolve_effect` is 3,508 bytes. The report also hashes exact repeated **function bodies** after excluding their distinct declaration headers: the baseline has 367 redundant body bytes, the 32-repeated cell 4,609, and the 16-diverse cell 4,161. These are source-body opportunities only; many near-identical schema bodies are excluded and AssemblyScript may already share or discard code. A prior source-only reduction producing identical Wasm is why final Wasm and compiler costs remain independent acceptance metrics.

Ranked follow-up experiments, with exact owners and predicted metrics:

1. **GEN03, structural schema projection sharing.** `generateSchemaRuntime` in `packages/provider-fastly/src/build/native-platform-capabilities.js` emits the per-schema value projectors and `__pulse_fastly_schema_apply`; `nativeSchemaCodecSource` in `wasm/packages/runtime-core-as/src/compiler/canonical-native.js` emits portable schema codecs. At fixed 16 IDs, diversity adds 30,646 source bytes (26,915 provider projection bytes), 55,232 final-Wasm bytes, 81 functions, and roughly 2.9 s of median ASC time. Probe structural helper reuse on equivalent *subshapes*, preserving each ID, validation, and dispatch; expect source/function/body changes and measure ASC time and RSS. Different shapes cannot simply be deduplicated. The repeated-ID comparison is a separate control: 1→32 IDs adds 66,463 source bytes but only 4,071 final-Wasm bytes, and does not justify a Wasm saving claim for an ID-only rewrite.
2. **GEN02, selective provider support emission.** The assembly source composition and `fastlyRuntimeSource` in `packages/provider-fastly/src/build/native-platform-capabilities.js` account for most of the stable 100,078-byte runtime-support bucket (212 declarations in these fixtures). Inventory support reachability by capability before changing composition. Predict lower generated source and potentially lower ASC parse/compile time and peak RSS; require byte-verified optional-support selection and target behavior checks. The shared JSON parser alone is 6,512 bytes and must remain when schema and effect parsing use it. This ledger gives no causal compiler-time or final-Wasm savings estimate for support gating.
3. **GEN04, bounded effect handoff/adapter factoring.** `effectResultSource` in `packages/provider-fastly/src/build/native-platform-capabilities.js` owns provider `__pulse_fastly_resolve_effect`; `generateCanonicalNativeAssemblyScript` in `wasm/packages/runtime-core-as/src/compiler/canonical-native.js` owns portable `pulse_set_effect_result` and handler chunks. Changing 8 routes from one to three sites adds 24,724 source bytes (22,151 dispatcher/handler, 2,572 package/effect adapter) but only 3,444 final-Wasm bytes and three final functions. Compare a bounded shared handoff helper and stable table representation against this cross-product; accept only measured source and compiler-cost improvements while preserving effect ordering and lifecycle. The three samples do not establish a compile-time increase for this route/effect contrast.

GEN01 deliberately creates no optimizer framework or public diagnostic. Its next experiment should capture an isolated before/after with the same fixtures and the SC01/B03 execution and binary-identity controls. All IDs remain registered in this census; there is no reachability deletion. Package composition, shape diversity beyond these examples, deployed Fastly cold start, and per-function optimized Wasm ownership are outside this result.
