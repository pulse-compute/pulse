# K2 — conditional KV runtime and Node reference

Implemented from `latest` at `b40a5c66b9e690be93ac3f852f11811d5f49db8f`
(K1, PR #9). [K1](K1.md) remains the semantic design record. This checkpoint
implements shared authoring/host contracts, compiler lowering and a deterministic
Node reference; it does not complete K3 or K4.

No single named Entry Point covers these owners. Work follows the ordinary
root-to-target instructions under Nathan's instruction to implement K2.
Classification: architecture. Boundaries: public authoring API, effects and
capabilities, continuation runtime, provider registry, runtime targets and the
internal workspace dependency/host export seam. No external dependency, release
identity, package set, publication, deployment or merge authority changes.

## Implemented owners

- `@pulse-compute/runtime` owns `PulseKvGeneration`, the discriminated read/write
  result types, the three namespace methods and the shared host boundary.
  `@pulse-compute/pulse` re-exports the types. Existing `get`/`put` remain available.
- The compiler recognizes literal KV namespaces, runtime keys/generations/values,
  direct awaited effects, scoped namespace locals and fixed keyed groups. Handler
  IR transports generation as a value input; Native plans classify results as
  structured JSON. Wasm retains the existing `effect_begin`/resume ABI and opaque
  host value handles; there is no Promise, Asyncify or provider SDK in the guest.
- The Node provider owns `createNodeKvReference` through its existing `./runtime`
  export. JavaScript bindings and Native adapters use that one implementation.
  The provider's existing descriptors advertise the three explicit capabilities.
- The Native host now declares a dependency on the existing workspace runtime
  package and imports its host seam, sharing admission, validation and lifecycle
  behavior. The generated lockfile change adds only that workspace link; every
  external package version and integrity stays pinned.
- Fastly JavaScript readiness explicitly reports conditional KV as incomplete.
  This is capability mapping, never Pulse's semantic authority or a blocker.
  No Fastly conditional adapter is implemented here.

## Authority and lifecycle

One Node reference is one local authority. Host code may reuse it across requests,
JavaScript bindings and Native adapters with `kvReference`. A static Node HTTP
handler owns persistent in-memory bindings for that handler. Native adapter base
values belong to that adapter's shared reference; explicit per-execution `kv`
fixture overrides retain execution isolation and are disposed with that execution.
A fresh helper/adapter/reference creates a fresh authority. No process-global
singleton, implicit disk persistence or globally durable claim is introduced.

Each instance has an identity and a monotonically allocated, nonreused 128-bit
sequence, encoded as `node-kv-v1:<identity>:<32 lowercase hex digits>`. Defaults
use a host-generated UUID; `kvInstanceId` and `kvGenerationStart` allow deterministic
host evidence. Applications only retain/replay the opaque token. Seed values and
unconditional replacements allocate generations too. Predicate and replacement
have no await or callback between them. Same-byte replacement changes generation.
Physical deletion/TTL remains outside the API.

Admission validates and detaches before dispatch. Native admission occurs in
`effect_begin`, before the guest can continue building the group. Generation,
key and value never pass through an SDK, numeric token conversion or an implicit
read/write CAS simulation. Strict wire decoding rejects duplicate members,
invalid UTF-8, legacy raw JSON, unsupported envelope fields and oversized values.
The read result is immutable; TypeScript generics do not validate domain schemas.

`prepareConditionalKv(effect, execution)` is a trusted host preparation seam.
It may resolve bindings or stage bytes but must not send. It returns a primitive;
entry into that function is the conservative dispatch boundary, even if it
throws synchronously. Custom adapters without preparation are conservatively
classified at entry into their dispatch function. Missing compatibility methods
produce configuration failures and never fall back to `get`/`put`.

The runtime bounds preparation, dispatch and completion by a monotonic ten-second
admission deadline, shortened by `deadlineMonotonicMs`. The host-only `kvClock`
allows deterministic clock/scheduler evidence. Before-dispatch timeout is
`not-stored`; post-dispatch timeout or lost acknowledgement is `unknown`. Complete
explicit rejection remains `not-stored`. No write acknowledgement invents a token.

Request cancellation follows each existing target's lifecycle: the JavaScript
Router returns its managed error response; Native/canonical test execution rejects
and disposes its continuation. An inactive application receives no typed success
or failure. `kv-lifecycle` evidence distinguishes dispatch and possible acceptance.
Timers/listeners are removed; late preparation cannot dispatch after cancellation
or expiry. Late completion cannot resume a disposed handler. Possible acceptance
is never reported as rollback.

Node `kvHooks.prepare`, `dispatch`, `afterCommit` and `read` are host-only test
injection points. They permit stalled preparation, reordered authority entry,
accepted-but-unconfirmed mutation and stale paired observations. They are not
application capabilities and do not change atomic predicate/mutation behavior.

## Evidence and commands

```sh
node wasm/scripts/run-wasm-tests.cjs --task kv-conditional-runtime --task kv-conditional-conformance --no-report
```

The production boundary corpus reuses K1 wire and 64-bit token vectors; adds
released-type positive/negative consumers; checks exact bounds, immutable
snapshots, invalid inputs without provider invocation, malformed results,
redaction and absence of unconditional fallback. It also closes an existing
array-accessor validation path that evaluated a getter while rejecting it.

The same [consumer](k2/consumer.ts) executes as JavaScript, actual compiled Wasm
and the canonical test runtime. It covers missing reads, present null, absent
CAS, same-byte replacement, stale writes, fixed keyed groups, twelve three-writer
schedules per target, K1's eight token round trips, stale observations, loss after
acceptance, pre/post-dispatch deadlines and cancellation. This is 78 scheduled
race/token/lifecycle scenarios plus ordinary operation assertions, typed schema
transport and lowering/readiness negatives. The tests use real runtime paths;
K1's reference model is not a production adapter or the mutation oracle.

The new tasks are registered in unit/conformance and mapped to the existing
schema/binding release-evidence shard. Broader checks cover unit, Native,
JavaScript, conformance, workspace build, package dependency containment and docs.
The PR records the commands actually completed and any remaining limitations.

## K3 and K4 handoff

K3 must implement the real Fastly Native operations behind the shared contract:
lossless generation metadata, conditional ADD/CAS options, complete error/output
mapping, bounded body acquisition, readiness/deadlines and cleanup. Preserve K1's
explicit zero-token condition presence. Use a 65,560-byte wire bound rather than
the old 65,536-byte Native buffer. There is no write-cancellation rollback promise.

The JS SDK remains incomplete mapping; no SDK repair/fork is required and no
weaker SDK behavior may redefine the contract. Fastly Native should move ahead
independently. Reuse the shared corpus when a target genuinely realizes it.

K4 owns expanded adversarial and exact packed-consumer acceptance, then deployed
cross-location evidence after T2. Local Node races do not establish Fastly
stale-writer exclusion, replication latency, durable recovery, physical-delete
nonreuse or Catalog's authoritative mutation path. Assets, S3 and Crypto remain
outside this change.
