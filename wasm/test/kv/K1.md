# K1 — conditional KV contract and provider mapping

Status: **design checkpoint implemented**, based on `latest` at
`6e1c1003a410a46877d25e1271689823b8ef9a2c` (O4, PR #8).

The [machine contract](k1/contract.json), [draft types](k1/api.d.ts),
[vectors](k1/vectors.json) and [provider mapping](k1/provider-mapping.json)
define the next Pulse capability. They do not advertise runtime support.
K2 owns shared/runtime/Node implementation; K3 owns Fastly realization;
K4 owns adversarial, packed and deployed acceptance.

Nathan explicitly directed that the JavaScript SDK is incomplete capability
mapping, never canon and never a blocker for other targets. This contract is
owned by Pulse. No SDK fork, provider SDK import in a handler, management API
transport substitute or read-then-write CAS emulation is required or allowed.
Assets, S3 and Crypto remain unchanged.

No exact Entry Point covers this cross-owner design checkpoint. It follows the
ordinary root and `wasm/AGENTS.md` instruction chain. Classification:
architecture, under the instruction to implement K1. The only integration
changes register the design/ABI tests and classify their release evidence;
they do not promote packages or add supported effects to production catalogs.

## Authoring and ownership

The new methods extend the existing `ctx.kv<T>('namespace')` surface; they do
not create a package or separate storage authority.

| Operation | Meaning |
| --- | --- |
| `getVersioned(key)` | Return one observed value and its opaque storage generation together. |
| `insertIfAbsent(key, value)` | Atomically store the value only if the key is absent at its authority. |
| `compareAndSwap(key, generation, value)` | Atomically replace an existing value only if its current generation equals the supplied token. |

Namespace selection is a compiler-proven literal using existing provider-owned
bindings. Key, generation and replacement value are runtime data. Direct await
and direct keyed `ctx.parallel` calls use the existing request-owned effect and
continuation lifecycle. K2 must add explicit `kv.getVersioned`,
`kv.insertIfAbsent`, and `kv.compareAndSwap` capabilities through authoring,
host contracts, lowering, Handler IR and dispatch. No generic Promise escape
or package-operation workaround is introduced.

Snapshot and validate values at effect admission before dispatch; later caller
mutation cannot change the dispatched candidate. Read values are bounded,
deeply immutable portable JSON data. TypeScript's `T` alone does not validate
an application schema. Catalog continues to own its domain validation,
authorization, object references, canonical bytes, command IDs, receipts,
reconciliation and rebasing. Generations convey no authorization.

## Semantics and results

The predicate and the mutation are one atomic operation at the authority for
the physical store/key. Two conditional writers carrying the same current
generation cannot both replace it. Two insert-if-absent writers cannot both
create the same absent key. Replacing identical bytes is still a write and
changes the generation. There is no multi-key transaction, automatic retry,
automatic refresh-and-retry, rebase or rollback.

`getVersioned` returns `found` with `value` and `generation`, `not-found`, or
`failed` with a bounded portable reason. Null is a present value; missing does
not carry a token. The bytes and generation must come from the same storage
observation. A read may be stale: neither a newer generation nor a later read
can be substituted while retaining bytes from an earlier observation. Failed,
oversized, invalid or incomplete reads do not expose a usable partial result.

| Write result | Meaning |
| --- | --- |
| `stored` | The provider completely acknowledged this conditional mutation as accepted. |
| `conflict` | A complete provider result establishes that this condition was false and this attempt did not write. |
| `not-stored` + reason | Validation/pre-dispatch failure, or a complete explicit rejection establishing no write. |
| `unknown` + reason | Dispatch may have reached the authority, and its disposition is unconfirmed. It may have committed. |

An absent key is a conflict for `compareAndSwap`. Conflict returns neither an
invented current value nor a guessed current generation or reason distinguishing
absence from mismatch. An explicit extra read is another potentially stale
observation. `stored` does not claim immediate visibility everywhere or a
durability level the provider has not demonstrated.

Write acknowledgement does **not** return a new generation. Fastly's insert
completion does not supply one, and a follow-up read might describe another
writer. The next versioned read supplies a token for its own observed value.

### Dispatch, timeout and cancellation

The dispatch boundary is entry into the first provider primitive that could
change storage, not successful return from it. Local encoding, credentials,
binding resolution, body staging and validation precede that boundary. A
synchronous exception from the send primitive cannot prove nothing was sent.

Timeouts before dispatch are `not-stored`; unconfirmed timeouts after dispatch
are `unknown`. A provider operation deadline must bound resolution, staging,
dispatch and completion; use a monotonic clock and the earlier of its own
10-second budget and any request deadline. K1 adds no public timeout options.
Request cancellation takes precedence over returning a typed result to an
inactive handler. It preserves the existing request lifecycle, cancels/discards
pending work where possible and never implies origin rollback. Host evidence
must distinguish cancellation before dispatch from possible acceptance after it.
An absent receipt in a stale read cannot turn `unknown` into `not-stored`.

## Generations, values and wire compatibility

Generations are opaque visible-ASCII strings of 1–256 bytes. Applications may
retain and replay them, not parse, increment, order or convert them to numbers.
Their scope is the same provider/store/key that produced the observation;
cross-key replay has no contract. Providers validate their own token encoding.
Tokens are not aggregate versions, representation versions or content hashes.

Fastly maps the unsigned 64-bit value to `fastly-kv-v1:` plus exactly 16 lowercase
hex digits. Host conversion preserves all bits, including the high bit, using
integer/byte operations. Zero is representable; it is neither an absent-key
token nor permission to omit the condition. This does not assert that every
representable token is issued by the service. A provider rejection must remain
explicit. A Node reference should use an instance identity and nonreused
generation identities with injectable deterministic identity inputs for tests.
It must not reset generations while exposing old tokens as usable in the same
instance. Its local model is not durable production storage.

| Bound | Contract |
| --- | --- |
| Logical namespace | Existing literal binding contract, up to 256 UTF-8 bytes |
| Exact key | 1–1,024 UTF-8 bytes; Unicode scalar values; no C0/C1 controls |
| Value | Existing portable KV JSON rules; at most 65,536 serialized UTF-8 bytes, depth 64, 10,000 visited values |
| Persisted envelope | At most 65,560 raw UTF-8 bytes, including wrapper overhead |
| Structured effect/result envelope | At most 262,144 encoded bytes |
| Operation deadline | 10 seconds from effect admission, shortened by the owning request deadline |

No normalization, URL decoding, namespace prefix insertion, JSON-domain
canonicalization or truncation occurs. For example, `#` and `..` are valid
Pulse exact keys; a target unable to represent them reports `invalid-key`
before dispatch. A provider's naming restrictions do not redefine Pulse.

All new conditional realizations write the same existing Native envelope:

```json
{"__pulseKv":1,"value":{"application":"data"}}
```

The exact top-level fields are `__pulseKv` (numeric 1) and `value`. The generation
is provider metadata, not a field in this JSON. Decode strict UTF-8 and JSON;
reject duplicate members, unknown/missing envelope fields, unsupported envelope
versions and invalid portable values. Whitespace, number spelling and member
order have no semantic significance. Catalog byte canonicalization remains a
separate operation. A user value resembling the wrapper remains nested in the
wrapper, with no recursive unwrapping.

This is **new conditional-operation wire compatibility**. Current Fastly Native
unconditional PUT already writes this envelope; current Fastly JavaScript
unconditional PUT writes raw JSON and GET returns it unchanged. K1 does not
silently reinterpret legacy raw JSON, change unconditional APIs, or promise
interchangeability of their legacy representations. `getVersioned` rejects raw
legacy data with `failed/protocol`; migration must be explicit. Mixed legacy
access requires a separately declared compatibility treatment. Catalog's
authoritative keys must use conditional operations for all application writes.
Existing unconditional operations remain available to their intentional callers.

K3 must exercise new readers/writers against the same persisted bytes across
targets, rather than independent fixtures that hide format disagreement. Its
Native body reader also needs to accommodate wrapper overhead beyond the current
65,536-byte buffer. This is a bounded capability change, not permission to lower
the admitted value limit or silently truncate.

## Provider mapping and evidence limits

| Target | Mapping / next gate |
| --- | --- |
| Node Native and Node JavaScript | One deterministic reference semantics and wire codec in K2; separate real canonical consumers. |
| Fastly Native | Direct host ABI in K3; no JavaScript SDK dependency. |
| Fastly JavaScript | Incomplete. No conditional eligibility until its own lossless capability path exists. Does not block other targets. |

Fastly's service documentation describes a 64-bit generation marker, changed
on updates, and a generation condition that prevents overwriting an intervening
write. This establishes a documented mapping for Pulse's single-key predicate;
it does not establish live cross-location conformance or token nonreuse across
deletion/recreation. [Service contract](https://www.fastly.com/documentation/reference/api/services/resources/kv-store-item/).

The Native mapping uses `lookup_wait_v2`'s eight-byte generation output, and
`insert` with a 32-byte options structure: mode at offset 0; generation at
offset 24. Insert-if-absent uses ADD mode 1. CAS uses overwrite mode 0 with
`IF_GENERATION_MATCH` mask 32; the flag stays present for zero bits. Reserved,
metadata, TTL and background-fetch fields are zero. The
[pinned ABI header](https://github.com/fastly/js-compute-runtime/blob/7d3a3394fc13c20c89359d4257d43b8562dcbf72/runtime/fastly/host-api/fastly.h)
is an external ABI mapping source, not Pulse semantic authority.

Only a successful hostcall makes its output slots trustworthy. For complete
insert completion: KV code 1 means stored; 4 means conflict; 3 means conflict
for CAS and unexpected/protocol for ADD; 2, 5 and 7 mean explicit rejection
(rejected, too-large, throttled). Code 6 is unknown/unavailable. Uninitialized
or unrecognized codes are unknown/protocol. A host failure after dispatch is
unknown even if an output slot happens to contain 1 or 4. Reads map 3 to missing;
5, 6 and 7 to too-large, unavailable and throttled failures; other non-OK codes
to protocol failure. Read host failures are transport failures; incomplete or
invalid bodies return the corresponding bounded failure. K3 must retain raw distinctions internally
and test actual call argument/result propagation; provider-specific error
codes and strings are not application return values.

The pinned JavaScript SDK drops the lookup generation, also narrows its host
tuple to 32 bits, and accepts write conditions through `Number`. This is a
capability gap to record, with no relaxation of token fidelity and no requirement
to repair that SDK. [Runtime](https://github.com/fastly/js-compute-runtime/blob/7d3a3394fc13c20c89359d4257d43b8562dcbf72/runtime/fastly/builtins/kv-store.cpp),
[host tuple](https://github.com/fastly/js-compute-runtime/blob/7d3a3394fc13c20c89359d4257d43b8562dcbf72/runtime/fastly/host-api/host_api.cpp).

Generation reuse after physical deletion/recreation is not an initial portable
promise. The optional nonreuse corpus must pass for a target to claim it.
Catalog can retain authority keys and represent deletion with conditional
tombstone values; TTL/physical deletion are outside these operations. Cross-key
atomicity, bounded replication latency and durable recovery are not inferred
from local models. K4's deployed gate must observe races, ambiguous completion,
visibility and any additional claimed guarantees after T2.

## Executable gate and following work

```sh
node wasm/scripts/run-wasm-tests.cjs --task kv-design-contract --task kv-native-abi-feasibility --no-report
```

The design test typechecks the future namespace without production module
augmentation; tests fixed token/byte/outcome vectors, portable value and wire
bounds, 12 three-writer schedules, stale reads, absent CAS, accepted-but-unconfirmed
writes, cancellation classification, same-byte replacement, and both nonreuse
and reuse across deletion/recreation. Eight token vectors include values above
`2^53`, the high bit and `2^64-1`. There are 31 fixed write/lifecycle outcome
vectors and 15 read outcome vectors.

The Native feasibility test compiles a standalone AssemblyScript probe and
executes its real Wasm against injected external host functions. It verifies
eight-byte lookup output to opaque token to insert-condition round trips,
options offsets/masks, invalid input rejection before send, ADD mode and host
failure handling. It is ABI feasibility, not the K3 adapter, the Fastly service
or a concurrency proof. Neither test uses an SDK implementation as its oracle.

K2 must add the declared shared operations and a Node reference implementation,
including schema/result transport, snapshots, real lifecycle failure injection,
deadlines and redaction of keys, tokens and values. K3 must add actual Fastly
Native bindings, bounded metadata/body acquisition, conditional options,
completion/error mapping, readiness/deadline handling and cleanup. There is no
pending-write cancellation/rollback promise; if the ABI cannot bound a wait,
record and resolve that Native capability gap rather than weakening Pulse.

K4 must replay the shared corpus through real target consumers and exact packed
packages, then perform deployed cross-location acceptance after T2. Local K1
success permits K2. It does not mark K2–K4 or the authoritative Catalog mutation
path complete. K1's new tasks are included in the existing design/historical
evidence shard so release aggregation will not encounter unmapped evidence.
