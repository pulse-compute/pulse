## Adapter and authority

`packages/provider-fastly/src/build/kv-native.as.ts` owns the direct Native
hostcall realization; `kv-native.js` generates its limits from the runtime's
existing host export. The Fastly platform generator selects it only for the
three explicit conditional kinds. The provider descriptor and Native target
advertise them. Source and verified Wasm are emitted together through the
existing platform compiler and final-import policy. No new dependency,
application option, SDK context, unconditional fallback, or release identity
is introduced.

The adapter validates exact keys and generation encodings before opening a
store. Fastly naming restrictions produce `invalid-key` before dispatch; no
normalization or key rewriting occurs. The existing logical-to-physical KV
binding selects the authority. Candidate serialization occurs at admission,
before binding resolution or body staging. The immutable string snapshot is
independent of the guest's original value.

`lookup_wait_v2` supplies the body and one `u64` generation observation. Integer
shifts preserve all bits in `fastly-kv-v1:` plus sixteen lowercase hex digits.
ADD uses mode 1 and mask 0; CAS uses mode 0, mask 32 and the generation at offset
24 in a zero-initialized 32-byte options structure. Zero bits still carry the
condition flag. Metadata, TTL, background-fetch and padding stay zero.

Only host status 0 validates completion outputs. Insert KV code 1 is stored;
4 is conflict; 3 is conflict only for CAS. Codes 2/5/7 are explicit rejection;
6 is unknown/unavailable; uninitialized or unexpected codes are unknown/protocol.
A failed hostcall after dispatch remains unknown even when an output slot
contains success or conflict. No acknowledgement manufactures a generation,
and no read, retry or rebase attempts to guess the mutation's disposition.

## Bounded lifecycle and transport

Each operation gets a monotonic ten-second deadline at admission. A host
embedding can shorten it with the provider-owned
`pulse_fastly_kv_request_deadline` Wasm export (absolute monotonic nanoseconds;
negative means no earlier deadline). It is not handler authority. Normal Compute
invocation uses the operation budget; platform termination ends the invocation.

The first insert hostcall is the conservative mutation boundary. Failures in
validation, binding resolution or body staging are not-stored. After dispatch,
unconfirmed timeout, transport loss or provider failure can mean acceptance.
Readiness selection always uses a positive bounded timeout: ABI timeout 0 means
an unbounded wait and is never sent. Pending lookup/insert waits and every read
of the returned body are preceded by readiness and deadline checks. A late
completion cannot override expiry. No unready pending handle is drained.

Successful insert transfers its staged body to the host. Locally owned bodies
are closed on preparation failure; acquired read bodies are closed on success,
invalid metadata, invalid wire, read failure and expiry. The ABI has no pending
KV cancellation operation. Expired pending handles remain owned by invocation
teardown; Pulse drops its continuation references and does not claim rollback.
A host trap or cancellation terminates Wasm and delivers no fabricated typed
result to an inactive handler. Local cancellation evidence distinguishes entry
before dispatch from possible commitment afterward.

The reader accepts at most 65,560 raw bytes, including wrapper overhead, with
strict UTF-8 and JSON decoding. It rejects duplicate members (including escaped
aliases), legacy raw JSON, extra/missing envelope members, unsupported versions,
non-finite values and portable size/depth/entry violations. Values are frozen
before guest resumption. Key/token/value strings are registered for log redaction;
ABI diagnostic traces omit them.

The maximum-value corpus exposed existing Native JSON transport defects. This
checkpoint also makes string parsing linear in input size, escapes isolated
UTF-16 surrogates, decodes request/body bytes across host chunk boundaries and
allows the depth-64 value plus its result/request wrappers in conditional plans.
Conditional numeric encoding removes AssemblyScript's extra `.0` on large
integral doubles so the portable serialized byte budget agrees with Node.
These fixes preserve valid conditional values through the existing handler
transport. Assets, Crypto and S3 package implementations are untouched.

## Executable gate and K4 handoff

```sh
node wasm/scripts/run-wasm-tests.cjs --task fastly-conditional-kv --no-report
```

The gate compiles K2's actual consumer into Fastly Wasm, then executes the
generated artifact against injected host functions. It reuses K1's token,
completion and wire vectors; checks all eight u64 round trips at the actual
argument/output pointers; and verifies ADD/CAS masks, offsets and zero padding.
It covers ordinary operations, three-writer schedules, keyed groups, paired
stale observations, missing CAS, same-value replacement, acceptance with lost
acknowledgement, malformed outputs, body and preparation failures, pre/post-send
deadlines, shortened request deadlines, cancellation and cleanup.

Node's production codec writes bytes read by Fastly Native; Native writes bytes
decoded by that same Node codec. Boundary cases include null, nested wrappers,
Unicode and surrogate escapes, split UTF-8 chunks, exact value bytes/depth/entry
limits, and large-number serialization budgets. Dedicated real-Wasm consumers
check detached mutable candidates and immutable read values. JavaScript readiness
stays blocked with `fastly-conditional-kv-incomplete`. The legacy JavaScript
fixture runtime has no Native KV ABI and returns a pre-dispatch configuration
failure for conditional KV; use this actual-Wasm gate or the Compute lane to
exercise the adapter. It never simulates CAS using its old get/put fixture maps.

The task is registered in conformance and the existing Fastly Native evidence
shard. The PR records completed unit, provider, Native, JavaScript, conformance,
build and documentation checks. Fastly CLI and Viceroy executables are unavailable
in this workspace; neither local Compute execution nor deployed acceptance is
reported as passed.

K4 can proceed on this Native adapter and K2's Node reference. It owns expanded
adversarial and exact packed-consumer acceptance, followed by deployed
cross-location evidence after T2. The injected authority models atomic writes;
it does not establish Fastly service race exclusion, replication delay,
durability, physical-delete token nonreuse or Catalog's authoritative mutation
path. Keep authority keys and conditional tombstones under the accepted K1
design until any stronger guarantee is separately demonstrated. The JS SDK's
capability gap is recorded independently and does not block this handoff.
